## 背景

`chatgpt-ops-rules` が共通運用ルールの正本として整備され、ChatExec2 Windows bat標準、FullFlow bat一括実行方針、個票先行main反映ゲート、worktree分離実行方針が共通運用ルールとして定義された。

`Q-Scout-for-Spring` 側にも、既存作業リポジトリとして `chatgpt-ops-rules` への中枢参照を導入し、共通運用ルールとQ-Scout固有仕様の分離を明確化する必要がある。

## 目的

`Q-Scout-for-Spring` に `chatgpt-ops-rules` への中枢参照を導入し、共通運用ルール正本とQ-Scout固有ルールの分離を明確化する。

## 想定作業

本個票は、個票先行main反映ゲートに従い、本体作業前に先行してmainへ反映する。

本体作業では、以下を検討・反映する。

1. Q-Scout側の作業開始導線に `chatgpt-ops-rules` 参照を追加する。
2. `README.md` / `docs/README.md` に中枢参照導線を追加する。
3. Q-Scout側に既存の横断運用規程入口がある場合は、中枢参照スタブ化する。
4. Q-Scout固有の業務仕様、実装仕様、公開仕様、評価仕様、環境依存手順はQ-Scout側に残す。
5. 共通運用ルール本文をQ-Scout側へ重複コピーしない。
6. 旧横断運用規程ファイル群が残っている場合は、Spring-Tool-Development-Template / APIM相当の整理が必要か判定する。
7. 反映後に発生・残存課題の未個票化がないか確認する。
