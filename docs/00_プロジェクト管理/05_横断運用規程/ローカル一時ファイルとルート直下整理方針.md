# ローカル一時ファイルとルート直下整理方針

## 1. 目的

本書は、Q-Scout for Springで発生するローカル一時ファイル、AI実行結果、外部実行スクリプト、実装支援AI指示書、検証ログを、リポジトリルートへ無秩序に残さないための方針を定める。

Q-ScoutはSpringプロジェクトの診断・改善支援系リポジトリであり、Codex、ChatExec2、GitHub Actions、ローカル検証を組み合わせて作業する機会がある。そのため、ルート直下にはプロジェクト入口、ビルド設定、起動・検証に必要な最小ファイルのみを残す。

## 2. 基本方針

1. ルート直下は、README、開始プロンプト、ビルドファイル、ラッパースクリプト、主要ディレクトリに限定する。
2. ChatExec、ChatExec2、Codex、その他AI支援作業の一時結果は、原則としてGit管理対象にしない。
3. 正規証跡として残すAI指示書、判断結果、運用規程は `docs/` 配下へ配置する。
4. 一時結果と正規文書を混同しない。
5. Q-Scout固有ではない派生プロダクト名、実行ログ、ローカル絶対パス、トークン、個人情報をコミットしない。

## 3. ルート直下に置いてよいもの

| 種別 | 例 | 備考 |
|---|---|---|
| プロジェクト入口 | `README.md`, 開始時プロンプト系文書 | 常時参照される入口文書 |
| ビルド設定 | `pom.xml`, `mvnw`, `mvnw.cmd`, `.mvn/` | Spring/Maven構成として必要なもの |
| CI設定 | `.github/` | GitHub Actions等に必要なもの |
| ソース・文書 | `src/`, `docs/`, `scripts/` | 正規管理対象 |

## 4. ルート直下に残さないもの

| 種別 | 例 | 方針 |
|---|---|---|
| 実行結果 | `ChatExec*.result`, `CodexExec*.result`, `*.out`, `*.err`, `*.log` | `.gitignore` 対象。必要ならサニタイズ済み要約のみPR/Issueへ記録 |
| ローカル詳細結果 | `.chatexec2/` | Git管理対象外 |
| 一時AI指示書 | `CodexExec_*.md` | 保存価値がある場合のみdocs配下へ移動。単発投入用は作業後に削除 |
| ビルド出力 | `target/`, `build/`, `out/` | Git管理対象外 |
| IDE個人設定 | `.vscode/`, `.idea/` | 原則Git管理対象外。ただし共有設定として必要なものは例外的に検討 |

## 5. CodexExec系Markdownの扱い

`CodexExec_*.md` は、一律にignoreしてはならない。

理由は、Codex投入指示書が後続レビューや再実行の正規証跡として有用な場合があるためである。

ただし、ルート直下へ置いたままにしない。扱いは以下の通りとする。

| 状態 | 対応 |
|---|---|
| 正規証跡として残す | `docs/00_プロジェクト管理/03_実装支援AI指示/` 等へ移動する |
| 一時投入用で再生成可能 | 作業完了後にローカル削除する |
| 誤ってtrackedになった | docs配下へ移動するか、重複確認後に削除する |
| 秘密情報を含む | コミットせず、即時削除し、必要に応じて履歴対策を検討する |

## 6. .gitignore標準候補

必要に応じて以下を `.gitignore` へ含める。

```gitignore
# AI execution result files
ChatExec.result
CodexExec.result
ChatExec*.result
CodexExec*.result
ChatExec*.summary.md
CodexExec*.summary.md
ChatExec*.log
CodexExec*.log
ChatExec*.out
ChatExec*.err
CodexExec*.out
CodexExec*.err
.chatexec2/

# Build outputs
target/
build/
out/
```

`CodexExec_*.md` は、上記の通り正規証跡になる場合があるため、一律ignore候補に含めない。

## 7. 確認手順

ルート直下が汚れている疑いがある場合、以下を確認する。

1. `git status --short --ignored` で未追跡・ignoredファイルを確認する。
2. `git ls-files` で誤ってtrackedになった一時ファイルがないか確認する。
3. ルート直下のMarkdown、result、log、out、errファイルを確認する。
4. 保存価値があるAI指示書はdocs配下へ移動する。
5. 保存不要な一時ファイルはローカル削除する。

## 8. 完了条件

ルート直下整理を完了扱いにするには、以下を満たす。

1. ルート直下に不要な一時結果ファイルが残っていない。
2. 保存すべきAI指示書がdocs配下へ移動済みである。
3. `.gitignore` が一時結果を適切に除外している。
4. 秘密情報、個人情報、ローカル絶対パスを含むファイルがコミットされていない。
5. Q-Scoutの診断・改善支援用途と矛盾しない内容に限定されている。
