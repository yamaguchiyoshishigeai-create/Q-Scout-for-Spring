# 運用ルール索引と実行ゲート

## 1. 目的

本書は、Q-Scout for Spring の作業開始時に、共通運用ルール正本とQ-Scout固有ルールの参照関係を確認するための入口文書である。

共通運用ルールの正本は `yamaguchiyoshishigeai-create/chatgpt-ops-rules` とする。

本書は、共通運用ルール本文をQ-Scout側へ重複コピーしない。詳細な共通規程は `chatgpt-ops-rules` 側を参照する。

## 2. 最優先参照先

| 区分 | 参照先 |
|---|---|
| 共通運用ルール正本 | `yamaguchiyoshishigeai-create/chatgpt-ops-rules` |
| 共通作業開始プロンプト | `chatgpt-ops-rules/PROJECT_START_PROMPT.md` |
| 共通横断運用規程入口 | `chatgpt-ops-rules/docs/00_プロジェクト管理/05_横断運用規程/00_運用ルール索引と実行ゲート.md` |
| Q-Scout側中枢参照方針 | `chatgpt-ops-rules中枢参照方針.md` |
| Q-Scout側改善タスク一覧 | `docs/00_プロジェクト管理/02_改善タスク管理/改善タスク課題一覧.md` |

## 3. 作業開始ゲート

Q-Scout for Spring の作業開始時は、以下を確認する。

1. Memory上のプロジェクト運用ルール。
2. `chatgpt-ops-rules` の `PROJECT_START_PROMPT.md`。
3. `chatgpt-ops-rules` の横断運用規程入口。
4. Q-Scout側の `PROJECT_START_PROMPT.md`。
5. Q-Scout側の `README.md`。
6. Q-Scout側の `docs/README.md`。
7. Q-Scout側の改善タスク課題一覧。
8. Open PRの有無。
9. 直前タスクのmerge、remote branch削除、worktree削除、local main同期、prune確認の完了状態。
10. Q-Scout固有の要件定義、設計、実装、公開サンプル評価文書。

## 4. 衝突時の優先順位

共通運用ルールとQ-Scout側文書に矛盾がある場合、共通運用ルールは `chatgpt-ops-rules` を優先する。

ただし、Q-Scout固有の業務仕様、実装仕様、環境依存手順、公開サンプル評価、製品前提はQ-Scout側文書を優先する。

## 5. 共通ルール本文の重複禁止

以下はQ-Scout側へ本文を重複コピーしない。

- ChatExec / ChatExec2方式の一般規程。
- ChatExec2 Windows bat標準。
- ChatExec2 FullFlow bat一括実行方針。
- ChatExec2 worktree分離実行方針。
- 通常PR自動merge方針。
- 個票先行main反映ゲート。
- Codex投入前ハンドオフゲート。
- 安全チェック発生時の仕様不変切替方針。
- 発生・残存課題の個票化最優先ルール。
- 実行計画と実行指示の分離方針。

必要な場合は、`chatgpt-ops-rules` の該当規程を参照する。

## 6. DONE判定

Q-Scout側の作業は、以下が完了するまでDONE扱いしない。

1. 対象PRがmainへmerge済みである。
2. 必要な課題管理整理が完了している。
3. remote作業ブランチが削除済みである。
4. JOB_ID worktreeが削除済みである。
5. 空の `<repo-name>-worktree` フォルダが削除済みである。
6. local mainがorigin/mainへ同期済みである。
7. `git worktree prune` と `git fetch origin --prune` が完了している。
8. remote tracking branchが残っていない。
9. 発生・残存課題の未個票化がないことを確認している。
