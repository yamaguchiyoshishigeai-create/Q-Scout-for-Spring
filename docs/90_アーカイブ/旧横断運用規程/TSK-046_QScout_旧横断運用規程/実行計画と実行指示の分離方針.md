# 実行計画と実行指示の分離方針

## 1. 目的

本方針は、ChatGPTがユーザーへ複数工程の作業を提示する際に、「今後の実行計画一覧」と「ユーザーが今実行すべき具体的な作業指示」を混同しないための横断運用規程である。

ユーザーが実行するコマンドや操作手順は、計画一覧の中に混在させず、実行タイミングが来た時点で対象Stepだけを明確に提示する。

## 2. 基本原則

- 実行計画一覧は、今後の進め方を共有するための概要である。
- 実行指示は、ユーザーまたはChatGPTが今から実行する具体的な作業である。
- ユーザーが行う作業は、原則としてその時点で必要な1ステップのみを提示し、結果を待つ。
- ユーザー実行結果を受けて、ChatGPT側で自動継続できる工程は、ユーザーへ再確認せずに進める。
- 次にユーザー操作が必要になった時点で、改めてそのユーザー向けStepだけを提示する。

## 3. 実行計画一覧を提示する場合

今後の全体像として複数Stepを提示する場合は、冒頭で「今後の実行計画一覧を提示する」旨を明示する。

実行計画一覧では、原則としてユーザーがそのまま実行できるコマンドをコードブロックで提示しない。

計画一覧に含める内容は、Step番号、実行主体、実施目的、成果物、後続分岐の概要に留める。

計画一覧の末尾でユーザー作業が必要な場合は、計画とは別に「次に実行するStep」として、当該Stepだけを実行指示として提示する。

## 4. ユーザー向け実行指示を提示する場合

ユーザーが実行する作業を提示する場合は、対象Stepのみを明確に提示する。

実行指示には以下を含める。

- Step番号。
- 実行主体。
- 理由。
- 実行内容。
- 成功条件。
- 失敗時に貼り付けるべき情報。

ユーザー向け実行指示に実行コマンドを含める場合、そのコードブロックは「今実行してほしい指示」として扱う。

## 5. コードブロックの扱い

実行コマンドを含むコードブロックは、原則として実行指示とみなす。

計画一覧、比較表、方針説明、将来工程の概要には、ユーザーがコピー実行できる形のコマンドを不用意に含めない。

コマンド例を説明として示す必要がある場合は、例示でありまだ実行しない旨を明記し、実行タイミングが来た時点で改めて対象Stepだけを実行指示として提示する。

## 6. 実行主体が混在する場合の進行

ユーザー、ChatGPT、Codexが混在する作業では、以下の順序で進める。

1. 現在必要なユーザー作業がある場合は、そのStepだけを提示する。
2. ユーザー結果を確認する。
3. ChatGPT側で自動実行可能な工程は、そのまま継続する。
4. Codex向け指示書作成やPR作成など、ChatGPT側で完結できる作業はユーザーへ実行指示として提示しない。
5. 次にユーザー操作が必要になった場合のみ、改めてユーザー向けStepを提示する。

## 7. 禁止事項

- 実行計画一覧として複数Stepを提示しながら、ユーザーが今実行すべきコマンドを紛れ込ませること。
- コードブロック付きコマンドを出したにもかかわらず、それが計画なのか実行指示なのか明示しないこと。
- ユーザー実行Stepの後に、ChatGPTが自動実行可能なStepまで計画として並べるだけで終了すること。
- ユーザー結果を受ければChatGPT側で進められる作業について、不要にユーザー指示待ちへ戻ること。
- ユーザー実行が必要な工程を計画一覧にだけ書き、最後に実行指示として再掲しないこと。
